## Prompt Handling

Lagere den Prompt spezifischen Code in `/home/user/xyan/xy.ai.workbench/src/xy/ai/workbench/AISessionManager.java` in einen PromptHandler in das Package `/home/user/xyan/xy.ai.workbench/src/xy/ai/workbench/connector/harness`.

Der PromptHandler empfängt den auslösenden Trigger, friert alle Eingaben ein in ein Prompt-Objekt(Ausgewählte Tools, Textbereich, Batch, Modell Konfiguration, Systemprompt)

- Konfigurationszustand `/home/user/xyan/xy.ai.workbench/src/xy/ai/workbench/ConfigManager.java`
- Der Aktivierungszustand des Session Processor muss zukünftig über das Promptobjekt steuerbar sein und soll nicht mehr direkt gesetzt werden
- Ziel ist die Kompatibilität zu einer Multi-Session Struktur mit möglichem Parallelbetrieb.
- Für das Fixieren der Konfiguration soll ein eigenes Objekt verwendet werden. Die semantische Trennung von Inputs, Batch und Konfiguration soll auch im Prompt-Objekt erhalten bleiben.

Der PromptHandler implementiert künftig die Kommandoerkennung und Inputauswahl.
Beispielweise parsed er bei einem `/call` Kommando den davor liegenden YAML block, für das Kommando, ausgehend von der Cursor-Position unabhängig davon ob dieser selektiert wurde. Anwendungsfall ist das convenient aktivieren eines Kommandos ohne vorherige auswahl.

### Prompt Object

Das Prompt-Objekt generiert eine Session ID auf Basis eine Hash der folgenden Parameter
- Absoluter Dateipfad der Datei in der, der Prompt initiiert wurden (Auf einem analogen Mechanismus basiert der Session Parameter Hash in `/home/user/xyan/xy.ai.workbench/src/xy/ai/workbench/connector/claudecode/SessionParameters.java`)
- Batch, 
- Einer Hash der eingefrorenen Konfiguration mit den Bestandteilen:
	- Model, Profile, Reasoning, Tools, Systemprompt, TopP, Temperature, Max Tokens

Alle Verwendungen der Konfiguration direkt in den Connectoren soll auf das Prompt-Objekt geändert werden.
- Statt einzelner Parameter, soll das Prompt Objekt in die Connectoren gereicht werden.
- Connectors: `/home/user/xyan/xy.ai.workbench/src/xy/ai/workbench/connector/claude/ClaudeConnector.java`, `/home/user/xyan/xy.ai.workbench/src/xy/ai/workbench/connector/deepseek/DeepSeekConnector.java`, `/home/user/xyan/xy.ai.workbench/src/xy/ai/workbench/connector/google/GeminiConnector.java`, `/home/user/xyan/xy.ai.workbench/src/xy/ai/workbench/connector/openai/OpenAIConnector.java`


## How to handle full editor mode and selection input mode?

Der PromptHandler erkennt ein Kommando im Input wie folgt:

1. check if selection is current line input, block selection or whole file input
	- on curent line input, check if current line starts with a command
	- on block selection, check if block starts with command (multi line commands) or contains a command starting at the last line (when postfixed to a tool call for example)
	- on whole file input ("Processor" Mode), first check current cursor line for command
		- Than check if the last line of the file starts with a command
		- commands everywhere else in a whole file input are assumed to be just sessions context

## MCP Call Command
Der MCP Client soll künftig einem zurückgegebenen Tool Call Template ein "/call" Kommando anstellen.
Beim Auslösen des Call-Kommandos, soll der PromptHandler das Kommando erkennen, parsen und typisiert, mittels Prompt-Objekt dem MCP-Client übergeben. Dabei erfasst der PromptHandler von der Zeile des Kommandos aus rückwärts den davorliegenden YAML Block (`^```yaml$`)

Zudem wird dem Template das "Tool:" Prefix vorangestellt.

- Prefix Konstanten: `/home/user/xyan/xy.ai.workbench/src/xy/ai/workbench/EditorInterface.java`
- Der Session Processor wird den Toolcall erkennen, in den richtigen Messagetyp umwandeln und das `/call` Kommando übergehen.
