# Warum dieser Wert kein YAML Block Scalar sein kann

Der gezeigte Wert ist **kein** Block Scalar (`|` oder `>`), sondern ein **doppelt gequoteter Flow-Scalar** (`"..."`). Wollte man ihn in einen Block Scalar umwandeln, gäbe es mehrere handfeste Kompatibilitätsprobleme:

### 1. `\n` sind Escape-Sequenzen, keine echten Zeilenumbrüche
In doppelten Anführungszeichen wird `\n` vom YAML-Parser in einen echten Newline übersetzt. In einem Block Scalar (`|`/`>`) gibt es **keine Escape-Interpretation** – dort wäre `\n` einfach der Buchstabe `\` gefolgt von `n`, also literaler Text statt Zeilenumbruch. Man müsste den String zuerst "entschärfen" (echte Newlines einfügen) und dann korrekt einrücken.

### 2. Escaped Anführungszeichen (`\"`)
Die `\"`-Sequenzen sind nur nötig, weil der String in `"…"` steht. Im Block Scalar bräuchte man das nicht – ein `"` ist dort ein ganz normales Zeichen. Ein blindes 1:1-Copy würde also unnötige Backslashes im Text hinterlassen.

### 3. Ein illegales Steuerzeichen (0x02) ist enthalten
Im Text taucht z. B. hier ein echtes, nicht druckbares Steuerzeichen (STX, `\x02`) auf:

```
...became a
Buddhaif he renounced\x02
the world...
```

Nach der YAML-Spezifikation dürfen in Scalars (egal ob Block oder Flow) nur **druckbare Zeichen** sowie Tab/LF/CR vorkommen (`c-printable`). Rohe C0-Steuerzeichen wie `0x02` sind **nicht erlaubt** – außer sie werden über eine Escape-Sequenz (`\x02`) dargestellt, was aber **nur im doppelt gequoteten Stil** möglich ist. Ein Block Scalar hat keine Escape-Syntax, kann dieses Zeichen also gar nicht repräsentieren. Das ist der entscheidende Blocker: Dieser String kann als reiner Block Scalar **prinzipiell nicht** verlustfrei dargestellt werden, solange das Steuerzeichen buchstäblich enthalten sein soll.

### 4. Struktur-/Einrückungsprobleme
Ein Block Scalar benötigt konsistente Einrückung über alle "physischen" Zeilen. Da der Text (nach Auflösen der `\n`) Zeilen enthält, die mit YAML-relevanten Zeichen beginnen könnten (z. B. `-`, `:`, `#`), müsste man beim Umbau in echte Zeilen zusätzlich prüfen, dass keine dieser Zeilen versehentlich als YAML-Struktur (Listenelement, Kommentar, Mapping-Key) interpretiert wird.

---

## Kurz gesagt
Der Block ist ein **doppelt gequoteter Scalar mit Escape-Sequenzen und einem eingebetteten, nicht druckbaren Steuerzeichen**. Ein Block Scalar kennt weder `\n`- noch `\"`-Escapes, und darf laut YAML-Spec generell keine rohen Steuerzeichen enthalten. Deshalb lässt sich dieser Wert nicht 1:1 in einen `|`- oder `>`-Block Scalar überführen – er müsste zuerst bereinigt (Steuerzeichen entfernt/ersetzt) und mit echten Zeilenumbrüchen neu formatiert werden.
